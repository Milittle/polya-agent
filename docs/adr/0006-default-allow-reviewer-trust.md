# 默认放行、审查器缝与项目信任门

审批曾是默认路径：每次 `write`/`exec` 都停车问一次，带 diff 预览、五选项、前缀授权
与会话规则。三轮打磨后它仍是交互层最大的复杂度来源——跨线程让位终端、脱离式选择器、
队列暂停/恢复状态机、四张权限表，且把「默认不信任自己的工具」写进了产品性格。用户
决定：审批从默认路径移除，默认以进程权限运行；未来的命令拦截交给**模型审查器**
（Jev 类），现在只留一条可插拔的缝。同时保留 plan 模式与「陌生目录资源不自动加载」
的安全叙事。

## Decision

三件事一起定：

1. **默认放行**。工具以 Polya 进程的操作系统权限运行，仅受 `--root` 路径监禁
   （`builtin._resolve` 拒绝 `../` 与绝对路径）。不再有逐调用审批、高危启发式、
   前缀授权与会话规则。
2. **审查器缝**（`polya/review.py`）。每次工具调用前经 `Reviewer.review(tool,
   arguments, *, plan, origin) -> Review`，结果只有 `allow` / `deny`。默认
   `AllowAllReviewer` 一律放行，仅在 plan 模式下拒绝非只读工具（`read` 与 `delegate`
   例外，后者的副作用在子调用上、子代理继承父 plan 再逐个过闸）。未来模型审查器实现
   同一协议即可接入。`deny` 只作为 tool 结果回传模型，不弹窗、不让位终端、不停整轮。
3. **项目信任门**（`polya/trust.py`）。首次在某目录启动时确认一次，记入
   `~/.polya/trust.json`（按绝对路径）。未信任目录**不加载**其 `AGENTS.md` 与项目
   skills——它们是当指令读的，可能是陌生仓库的提示注入；工具照常运行。非交互
   （`-p`/管道）不弹门，未信任即不加载，`--trust` 显式声明。

配套：Agent 去掉 `approve` / `approve_plan`，改 `reviewer`；plan 状态翻转归驱动层
（`leave_plan_mode()`）；`exit_plan_mode` 只打印计划并结束本轮，用户以 `/plan go` 或
精确批准白名单消息放行（见 `.scratch/pi-interaction/spec.md`）。

## Considered Options

- **保留逐调用审批，只精简 UI**：复杂度仍在，且与「默认放行」的模型性格冲突。
- **彻底删除一切门**：失去对陌生仓库提示注入的防线；AGENTS.md 是任意指令，不该
  在未确认的目录自动进系统提示词。
- **现在就实现模型审查器**：协议与展示（问什么、超时、deny 文案）未烤，先留缝。

## Consequences

- 安全边界从「逐次人工确认」变为「进程权限 + root 监禁 + 项目信任门 + （未来的）
  模型审查器」。README 必须写明默认放行，不再宣传逐次审批。
- 交互层净删约 1300 行（`approval.py` / `permissions.py` 及其测试），删掉终端让位
  握手与队列暂停状态机；输入改为 pi 式 steering / follow-up / abort。
- `/permissions`、`/resume`、`--yes` 移除；新增 `--trust`。
- 未来接入模型审查器时不需要把审批栈加回来；若需要「ask」出口，再引入同一编辑器内的
  inline 确认，不复用已删的脱离式选择器。
- 修订 ADR 0002 中「审批与工具执行外移至驱动层」的表述：外移的现在是**审查**，不是
  交互式审批。
